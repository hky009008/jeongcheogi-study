D007 · UI 표준·지침 — 요구사항과 구별, 설계 4원칙·UI 유형

2026-10-09 · A2 소프트웨어 개발 > 화면 설계

오늘부터 A2 화면 설계예요. 회사 디자인 시스템(버튼 모양·색·레이아웃 규칙)과 “이번 프로젝트 주문 조회 화면 요구”는 서로 다른 문서죠. 시험은 이 구분을 UI 표준 · UI 지침 · UI 요구사항이라는 말로 물어요. 여기에 단골 암기거리 세 묶음 — 설계 4원칙(직유학유), UI 유형(CLI·GUI·NUI·OUI), 요구사항 확인 절차 — 를 붙이면 오늘 분량이에요.

  • UI 표준(전체 시스템 공통 화면 규약) · UI 지침(개발할 때 지킬 공통 조건·가이드라인) · UI 요구사항(이 시스템 사용자의 UI 요구)을 구별한다
  • UI 설계 4원칙(직관성·유효성·학습성·유연성)을 설명을 보고 고를 수 있다
  • UI 유형 CLI·GUI·NUI·OUI를 조작 방식으로 구별한다
  • UI 요구사항 확인 절차(목표 정의 → 활동 사항 정의 → UI 요구사항 작성)와 작성 순서, 요구 요소 4종을 구별한다
  • 대표 UI 지침 키워드(사용자 중심·일관성·가시성·접근성·오류 안내)와 KWCAG 4원칙 이름을 알아본다

1. 큰 그림 — A2 화면 설계 지도

출제기준에서 A2 “화면 설계”는 세부항목 두 개, 세세항목 다섯 개예요. 오늘은 왼쪽 위 두 칸(UI 표준, UI 지침)을 맡고, 같은 상자에 있는 스토리보드와 아래 상자의 감성공학은 내일(D008) 몫이에요.

2. 표준 → 지침 → 요구사항, 세 문서의 관계

세 가지는 범위로 구별하면 쉬워요. 표준·지침은 조직·전체 시스템에 걸쳐 재사용하는 공통 규칙이고, 요구사항은 이번 시스템, 이번 사용자 이야기예요. UI 요구사항은 표준·지침에 의거해서 확인해요.

구분UI 표준UI 지침UI 요구사항
한 줄 정의전체 시스템의 모든 UI에 공통 적용할 화면 규약개발 과정에서 꼭 지켜야 할 공통 조건·가이드라인이 시스템 사용자가 원하는 UI 기능·품질
범위전사·전체 시스템전사·전체 시스템(개발 시 제약)이 프로젝트
현업 비유모든 화면 상단 GNB, 버튼 위치, 화면 이동 규칙 (디자인 시스템)오류 메시지엔 원인+해결 방법, 색만으로 정보 전달 금지“주문 조회에서 기간 검색 결과가 3초 안에 표시”
목적일관된 UI → 사용성 향상요구사항·구현 제약을 공통으로 지키게표준·지침에 의거해 이 SW에 적용할 UI 확정
시험 키워드전체 공통, 화면 구성, 화면 간 이동지켜야 할 공통 조건, 가이드라인정황 시나리오, 요구 요소
표준 = 통일할 규약, 지침 = 지킬 조건, 요구 = 이번 사용자의 바람. 선지에 “화면 구성 · 화면 간 이동 · 모든 화면 공통”이 보이면 표준.

※ 표준과 지침의 경계는 자료마다 조금 흐릿해요(지침 설명에도 “공통”이 들어가요). 시험은 대개 “전체 시스템 공통의 화면 구성·이동 규약 = UI 표준” 키워드로 물으니 그 짝을 먼저 잡으세요.

표준과 지침의 정의를 서로 바꿔 놓은 선지가 단골이에요. “화면 구성·이동 규약”이 지침 설명에 붙어 있으면 ✕.

3. UI 설계 4원칙 — 직유학유

원칙뜻현업 예함정
직관성누구나 쉽게 이해하고 바로 쓸 수 있게휴지통 아이콘 = 삭제, 설명 없이 알아봄↔ 학습성
유효성사용자의 목적을 정확하고 완전하게 달성하게결제 화면에서 결제가 끝까지 제대로 됨빠르기 ✕
목적 달성
학습성초보도 쉽게 배우고 기억하게한 번 써 보면 다음에도 같은 위치·흐름↔ 직관성
유연성다양한 사용자·조작을 최대한 포용하고 실수를 막아 줌단축키·마우스 모두 지원, 삭제 전 확인·되돌리기커스터마이징만 ✕
직유학유 = 이해 · 달성 · 배움 · 포용. “실수 방지·오류 최소화·초보~숙련자 모두” → 유연성.
직관성 ↔ 학습성: “처음 봐도 바로 안다” = 직관성, “쉽게 배워 익힌다” = 학습성. 두 정의를 바꾼 선지를 조심하세요.

※ 유효성의 영어를 effectiveness(목적 달성)로 쓰는 자료가 많지만 efficiency(효율)로 적은 자료도 있어요. 시험 문구는 “목적을 정확·완벽하게 달성”이 일반적이에요.

4. UI 유형 — 무엇으로 조작하나

유형풀이조작 방식예
CLICommand Line Interface키보드로 텍스트 명령어 입력터미널, DOS
GUIGraphical User Interface아이콘·창·메뉴를 마우스로Windows, macOS 데스크톱
NUINatural User Interface사람의 자연스러운 몸짓: 터치·제스처·음성핀치 줌, 스와이프
OUIOrganic User Interface사물 자체가 입출력 장치가 되는 유기적 UI웨어러블, IoT 기기 표면
기출 포인트: “터치·제스처 등 신체의 자연스러운 동작으로 조작” → NUI. GUI와 NUI를 섞은 선지가 자주 나와요.

※ 음성만 따로 떼어 VUI(Voice UI)라고 부르기도 하지만, 수험 자료는 대개 NUI 안에 포함해요.

5. UI 요구사항 확인 절차

큰 순서는 세 단계예요. 이름이 모두 평범해서 순서를 묻는 문제로 나와요.

① 목표 정의인터뷰로 비즈니스 요구·목표 정의
→
② 활동 사항 정의비전 일치·예산·일정·우선순위
→
③ UI 요구사항 작성실사용자 중심으로 작성

③ 안쪽도 다시 세 단계예요.

요구사항 요소 확인무엇을 담을지
→
정황 시나리오 작성육하원칙, 초기 시나리오
→
요구사항 작성시나리오에서 요구 도출

정황 시나리오는 “누가 언제 어디서 무엇을 왜 어떻게 쓰는가”를 이야기처럼 적은 초기 시나리오예요. 유저 스토리의 서술형 버전이라고 보면 돼요. 확인할 요구사항 요소는 네 가지예요.

데이터 요구화면이 다룰 데이터·속성 (예: 주문번호·일자·금액)
기능 요구사용자가 하려는 일, 동사형 (조회한다·취소한다)
제품·서비스 품질사용성·응답 시간 같은 품질, 감성 품질 포함
제약사항기한·비용·규제·기술 환경
목·활·작 — 목표 정의 → 활동 사항 정의 → 작성. 작성 안에서는 요소 → 시나리오 → 작성.
“화면 결과가 3초 안에 표시” 같은 시간·성능 조건은 비기능 요구사항이에요(품질 요구). “조회할 수 있다”처럼 동작을 말하면 기능 요구.

※ UI 품질 요구는 ISO/IEC 9126의 6특성(기능성·신뢰성·사용성·효율성·유지보수성·이식성)으로 정리하는 자료가 많아요. 후속 표준 ISO/IEC 25010은 특성이 8개(2011판)로 늘었어요. 품질 특성 자체는 뒤 과목에서 자세히 다뤄요.

6. 대표 UI 지침과 웹 접근성

“UI 설계 지침”으로 자주 나오는 키워드예요. 기출에서는 이 중 하나를 살짝 비튼 선지가 정답(옳지 않은 것)이 돼요.

사용자 중심개발자가 아니라 실사용자 기준으로
일관성버튼·용어·조작 방식이 화면마다 같게
가시성주요 기능을 메인 화면에 노출, 바로 찾게
접근성나이·장애·환경과 관계없이 쓸 수 있게
오류 안내이해하기 쉬운 메시지 + 복구 방법, 색·소리로 보조
피드백조작 결과·진행 상태를 즉시 알려 줌
“심미성을 사용성보다 우선”은 틀린 선지예요. UI 설계에서 우선은 언제나 사용성. 또, 오류 메시지를 “전문 용어로 정확히만” 쓰라는 선지도 ✕ — 사용자가 이해하고 복구할 수 있어야 해요.

웹 접근성은 한국형 웹 콘텐츠 접근성 지침(KWCAG)이 기준이에요. 4원칙 이름만 확실히 잡아 두세요.

KWCAG 원칙뜻예
인식의 용이성모든 콘텐츠를 사용자가 인식할 수 있게이미지 대체 텍스트, 자막
운용의 용이성UI 구성요소를 조작·이동할 수 있게키보드만으로 조작
이해의 용이성콘텐츠와 조작법을 이해할 수 있게명확한 입력 오류 안내
견고성여러 브라우저·보조기술에서도 동작표준 마크업
인운이견 — 인식·운용·이해·견고. W3C WCAG의 POUR(Perceivable · Operable · Understandable · Robust)와 같은 구조예요.

※ KWCAG 2.2(2022-12 개정) 기준 4원칙 · 14지침 · 33검사항목이에요. 지침 개수는 버전마다 달라 원칙 이름 위주로 기억하세요.

7. 시험 포인트 정리

  • “전체 시스템 공통 · 화면 구성 · 화면 간 이동 규약” → UI 표준
  • “개발 과정에서 꼭 지켜야 할 공통 조건” → UI 지침. 요구사항은 표준·지침에 의거해 확인
  • 설계 4원칙 직유학유: 이해(직관) · 목적 달성(유효) · 배움(학습) · 포용·실수 방지(유연)
  • 터치·제스처 → NUI, 텍스트 명령 → CLI, 아이콘·마우스 → GUI, 사물 자체 → OUI
  • 확인 절차 목표 정의 → 활동 사항 정의 → UI 요구사항 작성(요소 확인 → 정황 시나리오 → 작성)
  • 지침: 사용성 우선(심미성 우선 ✕), 오류 메시지는 이해 쉽게 + 복구 방법, 피드백
  • KWCAG 4원칙 인운이견
