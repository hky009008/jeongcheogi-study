0. 시작 전에 — 기본 전제와 용어 사전

핵심 한 줄 복잡도는 “입력이 아주 많을 때, 기본 연산을 몇 번 하나”를 재는 말이에요. 이 세 단어의 뜻부터 맞춰요.

복잡도 설명이 어렵게 느껴지는 건 대개 계산이 아니라 약속을 모르고 시작해서예요. 교재는 아래 전제를 당연하게 깔고 설명해요. 먼저 그 약속을 꺼내 놓을게요.

1. 왜 ‘몇 초’가 아니라 ‘몇 번’인가

핵심 한 줄 시간 복잡도는 상품 수 n이 늘 때 연산 횟수가 얼마나 빨리 늘어나는지를 재는 자예요.

쇼핑몰 상품을 정렬하는 코드가 내 노트북에서 1초 걸렸다고 해 볼게요. 서버에서 돌리면 0.1초일 수도 있고, 다른 프로그램이 같이 돌면 3초일 수도 있어요. 초는 기계와 상황에 따라 바뀌니까 알고리즘끼리 비교하는 자로는 못 써요.

그래서 대신 연산을 몇 번 하는지를 세요. 비교 한 번, 값 교환 한 번을 1로 치고, 그 횟수를 상품 수 n의 식으로 써요. 이 식은 어느 컴퓨터에서 돌려도 똑같아요.

그리고 진짜 궁금한 건 지금 몇 번이냐보다 상품이 늘면 어떻게 되느냐예요. 오픈 첫날 상품 100개일 땐 아무 방법이나 빨라요. 상품이 백만 개가 됐을 때 버티느냐가 문제예요. 아래 표가 그 차이예요. 컴퓨터가 1초에 10억 번 계산한다고 쳤어요.

등급상품 1,000개상품 1,000,000개백만 개일 때 걸리는 시간
O(log n)약 10번약 20번눈 깜짝할 새
O(n)1,000번100만 번0.001초
O(n log n)약 1만 번약 2,000만 번0.02초
O(n²)100만 번1조 번약 17분

상품 천 개일 땐 O(n²)도 0.001초라 아무도 몰라요. 백만 개가 되는 순간 정렬 버튼 하나에 17분이 걸려요. 같은 기능인데 n log n이면 0.02초예요. 시간 복잡도는 이렇게 규모가 커질 때 터지는 코드를 미리 알아보려고 쓰는 거예요.

2. 등급 여섯 개를 실제 상황으로 — 알고리즘을 직접 돌려 보기

핵심 한 줄 등급마다 쇼핑몰 장면 하나와 그 장면을 푸는 알고리즘 하나를 짝지어, 실제 데이터로 한 단계씩 돌려 보고 몇 번 했는지 세요.

여기서부터는 외우는 게 아니라 손으로 따라가는 장이에요. 각 등급을 같은 순서로 봐요. 먼저 어떤 상황에서 생기는 일인지, 그 상황을 푸는 알고리즘이 무엇인지 보고, 작은 데이터로 실제로 돌려 본 다음, 마지막에 몇 번 했는지 세서 등급을 붙여요.

2-1. O(1) — 장바구니의 3번째 상품 열기

어떤 상황?고객이 장바구니에서 3번째 상품을 눌렀어요. 장바구니에 3개가 있든 3만 개가 있든, 화면은 바로 떠야 해요.
무슨 알고리즘?배열 인덱스 접근. 칸 번호로 그 칸을 바로 읽는 것. 탐색이 아니라 ‘주소 계산’이에요.

배열은 메모리에 같은 크기의 칸을 빈틈없이 한 줄로 붙여 둔 거예요. 칸 크기가 모두 같으니, 몇 번째 칸이 메모리 어디에 있는지는 앞 칸을 하나도 안 보고 곱셈 한 번으로 나와요. 아파트 동·호수를 알면 1층부터 문을 두드리지 않고 바로 찾아가는 것과 같아요.

동작 순서① 배열 시작 주소를 안다
② 주소 = 시작 주소 + 칸 번호 × 칸 크기
③ 그 주소를 바로 읽는다

시작 주소가 1000번지이고 칸 하나가 8바이트라고 하면 이렇게 돼요.

읽을 칸계산주소연산 횟수
items[0]1000 + 0 × 810001번
items[2] (3번째)1000 + 2 × 810161번
items[29999] (3만 번째)1000 + 29999 × 8240,9921번
Item third = items[2];   // 칸 번호로 바로 → 상품 수와 상관없이 1번

세기: 상품이 3개든 3만 개든 계산은 1번이에요. 입력 크기 n과 상관없이 일정하니 O(1) 상수 시간이에요. 해시 탐색이 평균 O(1)인 것도 같은 원리예요. 상품번호로 칸 번호를 계산해서 바로 가니까요(3장에서 직접 해 봐요).

“i번째 상품 읽기”라도 연결 리스트(각 칸이 다음 칸 위치만 아는 구조)면 앞에서부터 i칸을 따라가야 해서 O(n)이에요. O(1)은 ‘배열이라 주소 계산이 된다’는 전제가 있어야 해요.

2-2. O(n) — 정렬 안 된 상품 중 최저가 찾기

어떤 상황?‘오늘의 특가’ 배너에 상품 6개 중 가장 싼 것을 띄워야 해요. 가격 목록은 등록 순서대로 섞여 있어요.
무슨 알고리즘?최솟값 찾기(순차 탐색). 처음부터 끝까지 하나씩 보면서 지금까지 가장 싼 값을 들고 다니는 방법.
동작 순서① 첫 상품 가격을 ‘지금까지 최저가’로 든다
② 다음 상품과 비교해서 더 싸면 바꿔 든다
③ 마지막 상품까지 반복
④ 손에 든 값이 답

가격(천 원) [5, 3, 8, 1, 9, 2]로 실제로 돌려 볼게요.

본 가격비교지금까지 최저가
5 (첫 칸)—5
33 < 5? 예 → 바꿈3
88 < 3? 아니오3
11 < 3? 예 → 바꿈1
99 < 1? 아니오1
22 < 1? 아니오1
int min = price[0];
for (int i = 1; i < n; i++)      // 1번 칸부터 끝까지 한 번
    if (price[i] < min) min = price[i];

세기: 6개에 비교 5번, n개면 n−1번이에요. 최고차항 n만 남겨 O(n) 선형 시간이에요. 상품이 2배면 시간도 딱 2배예요.

왜 중간에 멈출 수 없을까요? 3번 칸에서 1을 찾았지만, 정렬이 안 돼 있으니 안 본 칸에 0이 있을지도 몰라요. 그래서 끝까지 다 봐야 해요. 상품번호로 상품 하나를 찾는 순차 탐색도 같은 모양이에요. 운이 좋으면 첫 칸에서 찾고(최선 1번), 운이 나쁘면 끝까지 가요(최악 n번).

2-3. O(log n) — 정렬된 상품번호에서 987번 찾기

어떤 상황?상품이 번호순으로 정렬된 상태로 저장돼 있어요. 고객이 상품번호 987을 검색했어요.
무슨 알고리즘?이진 탐색. 가운데와 비교해서 절반을 통째로 버리는 걸 반복하는 방법. ‘업다운 숫자 맞히기’ 게임 그대로예요.

업다운 게임에서 1~100 사이 숫자를 맞힐 때 1, 2, 3… 부르는 사람은 없죠. 50을 부르고 “다운”이면 1~49만 남기고, 25를 불러요. 매번 남은 범위의 가운데를 부르면 범위가 절반씩 줄어요. 이게 이진 탐색이에요.

동작 순서① 범위를 처음~끝(lo~hi)으로 잡는다
② 가운데 칸 mid = (lo+hi)/2와 비교
③ 같으면 끝, 찾는 값이 작으면 오른쪽 절반 버리고(hi = mid−1), 크면 왼쪽 절반 버린다(lo = mid+1)
④ 범위가 빌 때까지 반복

상품번호 [102, 215, 348, 410, 523, 671, 734, 856, 912, 987](0~9번 칸)에서 987을 찾아요.

회차남은 범위가운데 칸과 비교
10~9칸 (10개)4번 = 523 → 987가 더 큼, 왼쪽 버림
25~9칸 (5개)7번 = 856 → 987가 더 큼, 왼쪽 버림
38~9칸 (2개)8번 = 912 → 987가 더 큼, 왼쪽 버림
49~9칸 (1개)9번 = 987 → 찾았다!
int lo = 0, hi = n - 1;
while (lo <= hi) {
    int mid = (lo + hi) / 2;          // 가운데
    if (id[mid] == x) return mid;      // 찾음
    if (x < id[mid]) hi = mid - 1;     // 오른쪽 절반 버림
    else             lo = mid + 1;     // 왼쪽 절반 버림
}
return -1;                             // 없음

세기: 10개에서 4번 만에 찾았어요. 남은 범위가 10 → 5 → 2 → 1처럼 매번 절반 이하로 줄어서, 최악이어도 “n을 반으로 몇 번 접으면 1이 되나” = log₂n 번 정도예요. 상품 100만 개도 20번이면 끝나요. 그래서 O(log n) 로그 시간이에요.

이진 탐색은 정렬된 자료에서만 돼요. 정렬이 안 돼 있으면 “987이 가운데 523보다 크니까 왼쪽 절반엔 없다”는 판단 자체가 성립하지 않아요.

2-4. O(n²) — 상품명이 중복된 게 있는지 확인하기

어떤 상황?판매자가 상품 4개를 한꺼번에 올렸어요. 그중 이름이 같은 상품이 있으면 경고를 띄워야 해요.
무슨 알고리즘?모든 쌍 비교. 상품 하나하나를 그 뒤의 모든 상품과 한 번씩 비교하는 방법. 반 친구 모두와 한 번씩 악수하는 것과 같아요.
동작 순서① 0번 상품을 1·2·3번과 비교
② 1번 상품을 2·3번과 비교(0번과는 이미 했으니 생략)
③ 2번 상품을 3번과 비교
④ 같은 이름이 나오면 중복

상품명 [모자, 양말, 장갑, 양말]로 돌려 봐요.

for (int i = 0; i < n; i++)             // 바깥: 상품 하나씩
    for (int j = i + 1; j < n; j++)     // 안쪽: 그 뒤 상품 전부
        if (name[i].equals(name[j])) dup = true;

세기: 4개에 6번 = 3 + 2 + 1, n개면 (n−1) + (n−2) + … + 1 = n(n−1)/2번이에요. 펼치면 n²/2 − n/2이고, 최고차항 n²만 남기면 O(n²) 제곱 시간이에요.

n이 10배가 될 때 일은 100배가 돼요. for 안에 for, 그러니까 “각각을 나머지 전부와”가 보이면 n²을 떠올리면 돼요. 4장의 버블·선택·삽입 정렬도 이 모양이에요.

2-5. O(n log n) — 상품 전체를 가격순으로 정렬

어떤 상황?상품 목록을 가격 낮은 순으로 보여 줘야 해요. 상품이 많아도 빨라야 해요.
무슨 알고리즘?병합 정렬(5장에서 직접 돌려 봐요). 반씩 쪼갠 다음, 정렬된 조각끼리 합치는 방법.

2-3의 ‘반씩’과 2-2의 ‘한 번씩 훑기’를 합친 모양이에요. 상품을 반, 또 반으로 쪼개면 층이 log n개 생기고, 각 층에서 조각들을 합칠 때 상품 n개를 한 번씩 만져요. 그래서 층 수 × 층마다 일 = log n × n = O(n log n)이에요. 상품 100만 개면 약 2,000만 번으로, n²의 1조 번과 비교도 안 되게 적어요.

2-6. O(2ⁿ) — 쿠폰 조합을 전부 따져 보기

어떤 상황?고객이 쿠폰 3장(A, B, C)을 갖고 있어요. 어떤 조합으로 쓰면 가장 싼지 모든 조합을 계산해 보려고 해요.
무슨 알고리즘?완전 탐색(모든 부분집합). 쿠폰마다 ‘쓴다 / 안 쓴다’ 두 갈래를 전부 시도하는 방법.
쿠폰 수가능한 조합개수
1장 (A){ }, {A}2
2장 (A, B){ }, {A}, {B}, {A,B}4
3장 (A, B, C){ }, {A}, {B}, {C}, {A,B}, {A,C}, {B,C}, {A,B,C}8
30장…약 10억

세기: 쿠폰이 한 장 늘 때마다 기존 조합 전부에 “새 쿠폰을 쓴다 / 안 쓴다”가 붙어서 개수가 2배가 돼요. n장이면 2ⁿ개, O(2ⁿ) 지수 시간이에요. 30장만 돼도 10억 개라, 실제 서비스에선 이렇게 안 짜요.

2-7. 여섯 개를 한 그림으로, 그리고 빅오로 줄이는 법

실제 코드는 위 모양이 여러 개 섞여 있어요. 예를 들어 중복 검사(2-4)를 하고 최저가(2-2)를 찾고 3번째 상품(2-1)을 열면 n(n−1)/2 + (n−1) + 1번이에요. 상품이 백만 개면 첫 항은 약 5천억, 둘째는 100만, 셋째는 1이에요. 5천억 앞에서 100만은 티도 안 나요. 그래서 가장 빨리 커지는 항만 남기고, 앞에 붙은 숫자(1/2 같은 계수)도 버려요. 그러면 O(n²)이에요.

등급 순서 1 < log n < n < n log n < n² < 2ⁿ — “주소 계산, 업다운, 한 줄 훑기, 쪼개서 합치기, 모두와 악수, 모든 조합”.

2-8. 최선·평균·최악과 O·Ω·Θ

2-2의 순차 탐색처럼 같은 알고리즘이라도 입력이 어떻게 생겼느냐에 따라 횟수가 달라요. 찾는 상품이 첫 칸이면 1번(최선), 중간쯤이면 n/2번(평균), 마지막 칸이거나 없으면 n번(최악)이에요. 시험은 이 셋을 기호와 짝지어 물어요. 그냥 “시간 복잡도”라고 하면 보통 최악을 뜻하는 빅오예요. “아무리 나빠도 이 이상은 안 걸린다”는 보증이라서요.

기호뜻순차 탐색 예
O 빅오상한 · 최악의 경우O(n) — 끝까지 가도 n번
Ω 빅오메가하한 · 최선의 경우Ω(1) — 첫 칸에서 찾음
Θ 빅세타상한과 하한이 같음 · 평균최솟값 찾기는 늘 n−1번 → Θ(n)
“빅오 표기법은 알고리즘의 최선의 경우를 나타낸다”(✗). 빅오는 최악(상한), 최선은 빅오메가예요. 오메가(Ω)는 바닥에 붙은 말굽 모양이라 ‘바닥 = 하한’으로 기억해요.

→ 이 장면의 결과물: 상황 → 알고리즘 → 돌려 보기 → 세기. 이 순서로 탐색을 하나 더 보고, 정렬로 넘어가요.

3. 남은 탐색 하나 — 해시로 상품 찾기

핵심 한 줄 상품번호를 계산해서 칸 번호를 얻으니 평균 O(1). 다른 번호가 같은 칸에 몰리면(충돌) 그 칸 안을 하나씩 봐야 해서 최악 O(n).
어떤 상황?상품번호로 상품을 찾는데, 정렬도 안 하고 이진 탐색보다 더 빨리 찾고 싶어요.
무슨 알고리즘?해시 탐색. 해시 함수가 키(상품번호)를 칸 번호로 바꿔 주고, 그 칸으로 바로 가는 방법. 사물함 번호를 계산해 주는 기계라고 보면 돼요.
동작 순서① 저장할 때: 칸 번호 = 해시 함수(상품번호), 그 칸에 넣기
② 찾을 때: 같은 계산으로 칸 번호를 구해 바로 가기
③ 그 칸에 여러 개가 있으면(충돌) 그 안에서 하나씩 비교

가장 단순한 해시 함수 “상품번호 ÷ 10의 나머지”로, 칸 10개짜리 테이블에 넣어 봐요.

상품번호계산 (÷10 나머지)들어간 칸찾을 때 비교
47234723 % 10 = 33번 칸1번
15881588 % 10 = 88번 칸1번
47214721 % 10 = 11번 칸1번
98219821 % 10 = 11번 칸 (충돌!)1번 칸 안에서 2번

세기: 보통은 계산 한 번 + 비교 한 번이라 평균 O(1)이에요. 그런데 상품번호가 전부 1로 끝나면 모두 1번 칸에 몰려서, 결국 그 칸 안을 순차 탐색하게 돼요. 그래서 최악 O(n)이에요.

4. 느린 정렬 셋 — 버블·선택·삽입을 직접 돌려 보기

핵심 한 줄 셋 다 바깥 반복 안에 안쪽 반복이라 평균·최악 O(n²)예요. 삽입만 이미 정렬된 입력에서 최선 O(n)으로 빨라져요.

상황은 하나로 고정해요. 상품 4개의 가격(천 원) [5, 3, 8, 1]을 낮은 가격 순으로 정렬해요. 같은 데이터를 세 방법으로 돌려 보고 비교 횟수를 세요. 표에서 굵은 숫자는 방금 건드린 칸 또는 확정된 칸이에요.

버블 정렬 — 이웃끼리 비교해서 큰 걸 뒤로

어떤 상황?가격표를 낮은 순으로 정렬해요.
무슨 알고리즘?이웃한 두 칸을 비교해 앞이 크면 맞바꾸는 걸 반복해요. 한 회차가 끝나면 가장 큰 값이 거품처럼 맨 뒤로 떠올라서 ‘버블’이에요.
동작 순서① 0·1번 칸 비교, 앞이 크면 교환
② 1·2번, 2·3번 … 끝까지 → 최댓값이 맨 뒤로(1회차 끝)
③ 맨 뒤 확정 칸을 빼고 다시 처음부터 반복
회차비교한 이웃배열
1회차5, 3 → 교환[3, 5, 8, 1]
1회차5, 8 → 그대로[3, 5, 8, 1]
1회차8, 1 → 교환[3, 5, 1, 8]
2회차3, 5 → 그대로[3, 5, 1, 8]
2회차5, 1 → 교환[3, 1, 5, 8]
3회차3, 1 → 교환[1, 3, 5, 8]
for (int p = 0; p < n - 1; p++)            // 회차: n-1번
    for (int j = 0; j < n - 1 - p; j++)    // 회차마다 하나씩 덜 비교
        if (a[j] > a[j + 1]) swap(a, j, j + 1);

세기: 4개에 6번 = 3 + 2 + 1이에요. 2-4의 ‘모두와 악수’와 똑같은 계단이라 n(n−1)/2 → O(n²)이에요. 입력이 어떻게 생겼든 이 계단을 다 밟아서 평균도 최악도 O(n²)이에요.

선택 정렬 — 남은 것 중 최솟값을 골라 앞으로

어떤 상황?같은 가격표를 정렬해요.
무슨 알고리즘?남은 칸을 전부 훑어 최솟값을 찾고(2-2의 최저가 찾기!), 그걸 남은 칸 맨 앞과 바꿔요. ‘제일 작은 걸 선택’해서 선택 정렬이에요.
동작 순서① 남은 칸 전체를 훑어 최솟값 찾기
② 그 값을 남은 칸의 맨 앞과 교환
③ 맨 앞 확정, 나머지로 반복
회차훑은 칸 → 찾은 최솟값교환 후 배열
1회차[5, 3, 8, 1] 비교 3번 → 최솟값 1[1, 3, 8, 5]
2회차[3, 8, 5] 비교 2번 → 최솟값 3[1, 3, 8, 5]
3회차[8, 5] 비교 1번 → 최솟값 5[1, 3, 5, 8]
for (int p = 0; p < n - 1; p++) {
    int m = p;
    for (int j = p + 1; j < n; j++)        // 남은 칸에서 최저가 찾기
        if (a[j] < a[m]) m = j;
    swap(a, p, m);                         // 맨 앞으로
}

세기: 역시 6번 = 3 + 2 + 1, O(n²)이에요. 회차마다 2-2의 최저가 찾기(O(n))를 n번 하는 셈이에요. 이미 정렬된 [1, 3, 5, 8]을 넣어도 비교는 6번으로 똑같아요. 최솟값인지 확인하려면 남은 걸 다 봐야 하니까요. 그래서 선택 정렬은 최선도 O(n²)이에요.

삽입 정렬 — 하나씩 꺼내서 알맞은 자리에 끼우기

어떤 상황?같은 가격표를 정렬해요.
무슨 알고리즘?카드 게임에서 새 카드를 받을 때마다 손에 든 카드 사이 알맞은 자리에 끼우는 방법이에요. 왼쪽은 늘 ‘이미 정렬된 부분’이에요.
동작 순서① 1번 칸 값을 꺼냄(0번 칸은 이미 ‘정렬된 부분’)
② 왼쪽으로 가며 자기보다 큰 값은 한 칸씩 뒤로 밀기
③ 자기보다 작은 값을 만나면 그 뒤에 끼우기
④ 다음 칸으로
꺼낸 값왼쪽과 비교 · 뒤로 밀린 값결과 (굵게 = 정렬된 부분)
35 (1번) · 밀림 5[3, 5, 8, 1]
85 (1번) · 밀림 없음[3, 5, 8, 1]
18, 5, 3 (3번) · 밀림 8, 5, 3[1, 3, 5, 8]
for (int i = 1; i < n; i++) {
    int key = a[i], j = i - 1;
    while (j >= 0 && a[j] > key) {     // 나보다 크면
        a[j + 1] = a[j]; j--;          // 한 칸 뒤로 밀고 더 왼쪽으로
    }
    a[j + 1] = key;                    // 빈자리에 끼우기
}

세기: 이번엔 5번이에요. 1을 꺼냈을 때 8, 5, 3을 다 거슬러 올라가느라 많이 들었어요. 거꾸로 정렬된 입력이면 매번 끝까지 거슬러 올라가서 1 + 2 + … + (n−1), 최악 O(n²)이에요.

그런데 이미 정렬된 [1, 3, 5, 8]을 넣으면 달라져요.

꺼낸 값왼쪽과 비교 · 뒤로 밀린 값결과
31 (1번) · 밀림 없음[1, 3, 5, 8]
53 (1번) · 밀림 없음[1, 3, 5, 8]
85 (1번) · 밀림 없음[1, 3, 5, 8]

꺼낼 때마다 왼쪽 이웃 하나만 보고 “나보다 작네, 여기 맞다” 하고 멈춰요. 비교 3번 = n−1번, 최선 O(n)이에요. 선택 정렬과 갈리는 지점이 바로 여기예요. 삽입은 ‘멈출 수 있고’, 선택은 ‘끝까지 봐야’ 해요.

버선삽은 n² — 버블·선택·삽입은 이중 반복 삼형제. 삽입만 “거의 정렬됐으면 O(n)” 특기가 있어요.

→ 이 장면의 결과물: 이웃끼리, 혹은 하나씩 비교하면 계단(n²)을 피할 수 없어요. 그럼 더 빠르게 하려면? 반씩 쪼개면 돼요.

5. 쪼개는 정렬 셋 — 병합·힙·퀵을 직접 돌려 보기

핵심 한 줄 병합·힙은 언제나 O(n log n). 퀵은 평균만 O(n log n)이고 최악은 O(n²)예요.

데이터는 4장과 같은 [5, 3, 8, 1]이에요. 세 방법 모두 ‘한꺼번에 다 비교하지 말고 쪼개서 일을 줄이자’는 생각에서 나왔어요.

병합 정렬 — 무조건 반으로 쪼갠 뒤, 합치면서 정렬

어떤 상황?가격표를 정렬하는데, 상품이 많아도 늘 일정하게 빨라야 해요.
무슨 알고리즘?분할 정복의 대표. 한 칸이 될 때까지 반으로 쪼개고(한 칸짜리는 이미 정렬된 것), 정렬된 두 조각을 ‘맨 앞끼리 비교’로 합쳐 올라와요.
동작 순서① 분할: 한 칸이 될 때까지 반으로 쪼갬
② 정복: 한 칸짜리는 이미 정렬된 것
③ 결합: 정렬된 두 조각의 맨 앞끼리 비교하며 작은 것부터 새 배열에 담아 합침
단계모습
분할 1층[5, 3, 8, 1] → [5, 3] | [8, 1]
분할 2층[5] | [3] | [8] | [1] (한 칸 = 정렬 끝)
결합 1층[5]+[3] → [3, 5] (비교 1번) · [8]+[1] → [1, 8] (비교 1번)
결합 2층[3, 5]+[1, 8] → ? (아래 표)

합치는 과정이 핵심이에요. 두 조각 모두 이미 정렬돼 있으니 맨 앞끼리만 비교하면 돼요. 두 줄로 선 사람들을 키 순서로 한 줄로 합칠 때, 두 줄의 맨 앞 사람만 비교해서 작은 사람을 먼저 보내는 것과 같아요.

맨 앞끼리 비교결과에 담은 값합친 결과
3 vs 11 (오른쪽)[1]
3 vs 83 (왼쪽)[1, 3]
5 vs 85 (왼쪽)[1, 3, 5]
한쪽이 빔남은 8 그대로 붙임[1, 3, 5, 8]
// 정렬된 L, R을 하나로 합치기
while (i < L.length && j < R.length)
    out[k++] = (L[i] <= R[j]) ? L[i++] : R[j++];   // 맨 앞끼리 비교
while (i < L.length) out[k++] = L[i++];            // 남은 것 붙이기
while (j < R.length) out[k++] = R[j++];

세기: 쪼개는 층이 log₂4 = 2개이고, 각 층에서 합칠 때 4개를 한 번씩 담아요. 층 수 × 층마다 n = n log n이에요. 입력이 정렬돼 있든 뒤죽박죽이든 ‘무조건 반’으로 자르니까 최선·평균·최악 모두 O(n log n)이에요. 대신 합칠 새 배열(out)이 n칸 더 필요해요(공간 복잡도 O(n)).

힙 정렬 — 최댓값이 늘 꼭대기에 오는 트리에서 하나씩 꺼내기

어떤 상황?가격표를 정렬하는데, 병합처럼 늘 빠르면서 새 배열은 쓰고 싶지 않아요.
무슨 알고리즘?배열을 최대 힙(부모 ≥ 자식인 완전 이진 트리)으로 정리하면 꼭대기가 늘 최댓값이에요. 꼭대기를 맨 뒤로 보내고, 남은 걸 다시 힙으로 정리하는 걸 반복해요.

힙은 그림은 트리지만 실제로는 배열에 그대로 담겨요. i번 칸의 자식은 2i+1번과 2i+2번 칸이라는 약속만 있으면 돼요. 그래서 [8, 3, 5, 1]은 꼭대기 8, 그 아래 3과 5, 3 아래 1인 트리예요.

동작 순서① 배열을 최대 힙으로 정리(부모가 자식보다 작으면 자리 바꿈)
② 꼭대기(최댓값)를 남은 배열 맨 뒤와 교환 → 맨 뒤 확정
③ 바뀌어 올라온 꼭대기 값을 자식 중 큰 쪽과 바꾸며 내려보내 다시 힙으로
④ 반복
한 일남은 힙확정된 뒤쪽
힙 만들기 (부모 ≥ 자식)[8, 3, 5, 1]—
꼭대기 8 ↔ 3번 칸, 남은 3개 다시 힙으로[5, 3, 1][8]
꼭대기 5 ↔ 2번 칸, 남은 2개 다시 힙으로[3, 1][5, 8]
꼭대기 3 ↔ 1번 칸, 남은 1개 다시 힙으로[1][3, 5, 8]

세기: ③에서 꼭대기 값이 내려가는 길이는 트리 높이, 즉 log n이에요. 이걸 n번 꺼내니 n × log n = O(n log n)이에요. 완전 이진 트리라 높이가 늘 log n으로 유지되니 언제나 O(n log n)이에요.

퀵 정렬 — 기준값으로 작은 쪽·큰 쪽 나누기

어떤 상황?가격표를 정렬해요. 평균적으로 가장 빠른 방법을 쓰고 싶어요.
무슨 알고리즘?기준값 피벗을 하나 골라 ‘피벗보다 작은 쪽 | 피벗 | 큰 쪽’으로 나누고, 양쪽을 같은 방법으로 다시 나눠요. 여기선 맨 앞 값을 피벗으로 잡아요.
동작 순서① 피벗 하나 고름(여기선 맨 앞)
② 분할: 나머지를 피벗과 하나씩 비교해 작은 쪽·큰 쪽으로 나눔
③ 양쪽 조각에 같은 방법을 반복(조각이 0~1칸이면 끝)
④ 작은 쪽 + 피벗 + 큰 쪽을 이어 붙이면 정렬 끝
나눌 조각피벗 (비교)작은 쪽큰 쪽
[5, 3, 8, 1]5 (3번)[3, 1][8]
[3, 1]3 (1번)[1][ ] 빔

피벗 5가 가운데쯤 값이라 [3, 1]과 [8]로 적당히 갈렸어요. 비교는 총 4번이에요. 이렇게 피벗이 매번 반쯤 가르면 병합처럼 층이 log n개라 평균 O(n log n)이에요.

이제 운이 나쁜 경우예요. 이미 정렬된 [1, 2, 3, 4, 5]를 넣고 똑같이 맨 앞을 피벗으로 잡아요.

나눌 조각피벗 (비교)작은 쪽큰 쪽
[1, 2, 3, 4, 5]1 (4번)[ ] 빔[2, 3, 4, 5]
[2, 3, 4, 5]2 (3번)[ ] 빔[3, 4, 5]
[3, 4, 5]3 (2번)[ ] 빔[4, 5]
[4, 5]4 (1번)[ ] 빔[5]

피벗이 매번 가장 작은 값이라 작은 쪽은 텅 비고, 큰 쪽은 딱 하나만 줄어요. 비교는 4 + 3 + 2 + 1 = 10번, 버블 정렬의 계단과 똑같은 n(n−1)/2예요. 그래서 최악 O(n²)이에요.

void quick(int[] a, int lo, int hi) {
    if (lo >= hi) return;                  // 0~1칸이면 끝
    int p = partition(a, lo, hi);          // 피벗 기준으로 작은 쪽|피벗|큰 쪽
    quick(a, lo, p - 1);                   // 작은 쪽 다시
    quick(a, p + 1, hi);                   // 큰 쪽 다시
}

D027 1번이 바로 이 지점을 물었어요. “평균과 최악이 모두 O(n²)”인 걸 찾으라고 했죠. 퀵은 최악은 O(n²)가 맞지만 평균은 O(n log n)이라 ‘모두’에서 빠져요. 위 두 표를 떠올리면 돼요. 첫 표(평균)는 쪼개는 쪽, 둘째 표(최악)는 계단 쪽이에요.

힙병은 철벽, 퀵은 운빨 — 힙·병합은 언제나 n log n. 퀵은 평균 n log n이지만 피벗 운이 나쁘면 n².

→ 이 장면의 결과물: 정렬 여섯 개를 같은 데이터로 직접 돌려 봤고, 평균·최악이 왜 그런지 표로 확인했어요. 남은 건 문제 문장에서 무엇을 보고 고르느냐예요.
