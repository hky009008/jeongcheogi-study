1. 왜 ‘몇 초’가 아니라 ‘몇 번’인가

핵심 한 줄 시간 복잡도는 상품 수 n이 늘 때 연산 횟수가 얼마나 빨리 늘어나는지를 재는 자예요.

쇼핑몰 상품을 정렬하는 코드가 내 노트북에서 1초 걸렸다고 해 볼게요. 서버에서 돌리면 0.1초일 수도 있고, 다른 프로그램이 같이 돌면 3초일 수도 있어요. 초는 기계와 상황에 따라 바뀌니까 알고리즘끼리 비교하는 자로는 못 써요.

그래서 대신 연산을 몇 번 하는지를 세요. 비교 한 번, 값 교환 한 번을 1로 치고, 그 횟수를 상품 수 n의 식으로 써요. 이 식은 어느 컴퓨터에서 돌려도 똑같아요.

그리고 진짜 궁금한 건 지금 몇 번이냐보다 상품이 늘면 어떻게 되느냐예요. 오픈 첫날 상품 100개일 땐 아무 방법이나 빨라요. 상품이 백만 개가 됐을 때 버티느냐가 문제예요. 아래 표가 그 차이예요. 컴퓨터가 1초에 10억 번 계산한다고 쳤어요.

2. 횟수를 세고, 빅오로 줄이기

핵심 한 줄 반복문 모양을 보면 횟수가 나오고, 그 식에서 가장 빨리 커지는 항 하나만 남기면 빅오예요.

코드 모양 네 가지만 알면 돼요

상품 배열 items로 네 가지 코드를 써 봤어요. 주석의 횟수를 따라가 보세요.

// 상품 n개가 든 배열 items
Item first = items[0];                 // ① 1번       → O(1)

for (int i = 0; i < n; i++)            // ② n번       → O(n)
    total += items[i].price;

for (int i = 0; i < n; i++)            // ③ n × n번   → O(n²)
    for (int j = 0; j < n; j++)
        if (items[i].name.equals(items[j].name)) dup++;

int k = n;                             // ④ n이 반씩: 8 → 4 → 2 → 1
while (k > 1) k = k / 2;               //    3번 = log₂8 → O(log n)

①은 첫 상품을 꺼내는 일이라 상품이 열 개든 백만 개든 1번이에요. 이게 O(1) 상수예요. ②는 상품을 처음부터 끝까지 한 번 훑으니 n번이에요. O(n) 선형이에요.

③은 상품마다 다른 모든 상품과 이름을 비교해요. 바깥 반복이 n번 돌고, 한 번 돌 때마다 안쪽이 또 n번 돌아요. 그래서 n × n = n²번이에요. for 안에 for가 보이면 O(n²)이라고 외워도 거의 맞아요.

④는 조금 다르게 생겼어요. k를 매번 반으로 줄여서 8 → 4 → 2 → 1, 세 번 만에 끝나요. “2를 몇 번 곱하면 8인가”가 log₂8 = 3이에요. 그래서 반씩 줄이는 반복은 O(log n)이에요. n이 백만이어도 스무 번이면 끝나요.

마지막 O(n log n)은 ②와 ④를 합친 모양이에요. 데이터를 반씩 쪼개는 층이 log n개 있고, 층마다 n개를 한 번씩 훑어요. 층 수 × 층마다 일 = log n × n이에요. 4장에서 병합 정렬로 직접 봐요.

빅오로 줄이는 법

실제 코드는 여러 모양이 섞여요. 예를 들어 ③을 하고 ②를 하고 ①을 하면 n² + n + 1번이에요. 상품이 백만 개면 n²은 1조, n은 100만, 1은 1이에요. 1조 앞에서 100만은 티도 안 나요. 그래서 가장 빨리 커지는 항만 남기고 앞에 붙은 숫자(상수)도 버려요. 3n² + 5n + 2도, n²/2도 전부 O(n²)이에요.

등급 순서 1 < log n < n < n log n < n² < n³ < 2ⁿ < n! — “한 번, 반씩, 한 줄, 쪼개서 한 줄씩, 겹쳐서, 세 겹, 모든 조합, 모든 순서”.

최선·평균·최악과 O·Ω·Θ

같은 알고리즘이라도 입력이 어떻게 생겼느냐에 따라 횟수가 달라요. 찾는 상품이 맨 앞에 있으면 1번 만에, 맨 끝에 있으면 n번 만에 찾아요. 그래서 운 좋은 경우(최선), 보통(평균), 운 나쁜 경우(최악)를 따로 말해요.

시험에서는 이 셋을 기호와 짝지어 물어요. 셋 중 빅오가 가장 많이 나와요. “아무리 나빠도 이 이상은 안 걸린다”는 보증서라서, 시간 복잡도라고 하면 보통 빅오(최악)를 말해요.

기호뜻쉽게

“빅오 표기법은 알고리즘의 최선의 경우를 나타낸다”(✗). 빅오는 최악(상한), 최선은 빅오메가예요. 오메가(Ω)는 바닥에 붙은 말굽 모양이라 ‘바닥 = 하한’으로 기억해요.

핵심 한 줄 하나씩 보면 n, 정렬해 두고 반씩 버리면 log n, 주소를 바로 계산하면 1.

고객이 상품번호 4721을 검색했어요. 가장 단순한 방법은 순차 탐색이에요. 첫 상품부터 하나씩 번호를 비교해요. 운 나쁘면 끝까지 가야 해서 n번, O(n)이에요. 대신 상품이 아무렇게나 섞여 있어도 쓸 수 있어요.

상품을 번호순으로 정렬해 두면 이진 탐색을 쓸 수 있어요. 가운데 상품 번호가 5000이면 4721은 앞쪽에 있을 테니 뒤쪽 절반을 통째로 버려요. 남은 절반의 가운데와 또 비교해요. 2장의 ④처럼 반씩 줄어드니 O(log n)이에요. 백만 개 중에서도 스무 번이면 찾아요. 단, 정렬돼 있지 않으면 쓸 수 없어요. 이 조건이 선지에 자주 숨어요.

해시 탐색은 상품번호를 해시 함수에 넣어 저장 칸 번호를 바로 계산해요. 사물함 번호를 알고 바로 가서 여는 것과 같아서 평균 O(1)이에요. 서로 다른 번호가 같은 칸으로 몰리는 충돌이 심하면 그 칸 안에서 다시 하나씩 찾아야 해서 최악 O(n)까지 느려져요.

핵심 한 줄 셋 다 바깥 반복 안에 안쪽 반복이라 평균·최악 O(n²)예요. 삽입만 이미 정렬된 입력에서 최선 O(n)으로 빨라져요.

버블 정렬 — 이웃끼리 비교해서 큰 걸 뒤로

동작 순서① 0번·1번 칸 비교, 앞이 크면 교환 ② 1번·2번, 2번·3번 … 끝까지 → 최댓값이 맨 뒤로(1회차 끝) ③ 맨 뒤 확정 칸을 빼고 다시 1회차부터 반복

가격표 [5, 3, 8, 1]을 버블 정렬해 볼게요. 맨 앞부터 이웃한 두 칸을 비교해서 앞이 크면 자리를 바꿔요. 한 회차를 끝까지 돌면 가장 큰 8이 거품처럼 맨 뒤로 떠올라요. 그래서 이름이 버블이에요.

2회차는 맨 뒤 8이 이미 자리를 잡았으니 하나 덜 비교해요. 3회차는 또 하나 덜 비교해요. 비교 횟수가 3, 2, 1로 계단처럼 줄어요. 아래 그림이 그 계단이에요.

상품이 n개면 (n−1) + (n−2) + … + 1 = n(n−1)/2번이에요. 펼치면 n²/2 − n/2이고, 2장 규칙대로 최고차항만 남기고 1/2도 버리면 O(n²)이에요. 중요한 건 입력이 어떻게 생겼든 이 계단을 다 밟는다는 거예요. 그래서 평균도 최악도 O(n²)이에요.

선택 정렬 — 남은 것 중 최솟값을 골라 앞으로

동작 순서① 남은 칸 전체를 훑어 최솟값 찾기 ② 그 값을 남은 칸의 맨 앞과 교환 ③ 맨 앞 확정, 나머지로 반복

선택 정렬은 남은 칸을 전부 훑어서 가장 작은 값을 찾고, 그걸 맨 앞자리와 바꿔요. 다음엔 둘째 칸부터 다시 훑어 최솟값을 찾아요. 남은 칸을 훑는 횟수가 역시 3, 2, 1로 줄어드는 계단이라 n(n−1)/2, O(n²)이에요.

선택 정렬의 특징은 이미 정렬된 입력이 와도 똑같이 느리다는 거예요. 최솟값인지 확인하려면 남은 걸 다 봐야 하니까요. 그래서 최선·평균·최악이 전부 O(n²)이에요.

삽입 정렬 — 하나씩 꺼내서 알맞은 자리에 끼우기

동작 순서① 1번 칸 값을 꺼냄(0번 칸은 이미 ‘정렬된 부분’) ② 왼쪽으로 가며 자기보다 큰 값은 한 칸씩 뒤로 밀기 ③ 자기보다 작은 값을 만나면 그 뒤에 끼우기 ④ 다음 칸으로

삽입 정렬은 카드 게임에서 손에 든 카드를 정리하는 방식이에요. 새 카드를 하나 받으면, 이미 정리된 카드들 사이에서 알맞은 자리를 찾아 끼워요. 앞에서부터 하나씩 꺼내 왼쪽 정렬된 부분과 비교하며 자리를 찾아요.

보통은 끼울 자리를 찾느라 왼쪽을 여러 칸 거슬러 올라가요. 그래서 평균·최악은 다른 둘처럼 O(n²)이에요. 그런데 상품이 이미 거의 정렬돼 있으면 왼쪽 이웃 하나만 보고 “여기 맞네” 하고 멈춰요. 아래 코드처럼 한 개당 1번, 총 n−1번이라 최선 O(n)이에요.

// 삽입 정렬 — 이미 정렬된 [1, 3, 5, 8]이면?
for (int i = 1; i < n; i++) {
    int key = a[i], j = i - 1;
    while (j >= 0 && a[j] > key) {   // 왼쪽 이웃이 이미 작으면
        a[j + 1] = a[j]; j--;          // 한 번 비교하고 바로 멈춤
    }
    a[j + 1] = key;
}
// 비교: 3이 1과 1번, 5가 3과 1번, 8이 5와 1번 = 3번 = n−1 → 최선 O(n)
버선삽은 n² — 버블·선택·삽입은 이중 반복 삼형제. 삽입만 “거의 정렬됐으면 O(n)” 특기가 있어요.

→ 이 장면의 결과물: 이웃끼리, 혹은 하나씩 비교하면 계단(n²)을 피할 수 없어요. 그럼 더 빠르게 하려면? 반씩 쪼개면 돼요.

5. 쪼개는 정렬 셋 — 병합·힙·퀵, 그리고 퀵의 함정

핵심 한 줄 병합·힙은 언제나 O(n log n). 퀵은 평균만 O(n log n)이고 최악은 O(n²)예요.

병합 정렬 — 무조건 반으로

동작 순서① 분할: 한 칸이 될 때까지 반으로 쪼갬 ② 정복: 한 칸짜리는 이미 정렬된 것 ③ 결합: 정렬된 두 조각의 맨 앞끼리 비교하며 작은 것부터 새 배열에 담아 합침

병합 정렬은 상품 8개를 4개·4개로, 다시 2개씩, 1개씩까지 무조건 반으로 쪼개요. 그다음 정렬된 조각 둘을 하나로 합치며 올라와요. 조각 두 개를 합칠 땐 각 조각 맨 앞끼리만 비교하면 되니 빨라요.

8개를 1개까지 쪼개는 데 세 번(log₂8 = 3), 즉 층이 3개예요. 층마다 합치는 일은 전부 합쳐 약 8번이에요. 그래서 층 수 × 층마다 일 = log n × n = n log n이에요. 입력이 정렬돼 있든 뒤죽박죽이든 반으로 자르는 건 똑같으니 최선·평균·최악이 모두 O(n log n)이에요. 대신 합칠 때 임시 배열이 필요해요.

힙 정렬 — 최댓값을 하나씩 꺼내기

동작 순서① 배열로 최대 힙을 만듦 ② 꼭대기(최댓값)를 배열 맨 뒤로 보냄 ③ 남은 트리를 다시 힙으로 정리(log n번) ④ 반복

힙 정렬은 상품을 힙(부모가 자식보다 항상 큰 완전 이진 트리)에 넣고, 꼭대기의 최댓값을 하나씩 꺼내요. 꺼낸 뒤 트리를 다시 정리하는 데 트리 높이만큼, 즉 log n번이 걸려요. n개를 꺼내니 n × log n이에요. 트리 모양이 늘 균형 잡혀 있어서 병합처럼 언제나 O(n log n)이에요.

퀵 정렬 — 평균은 가장 빠른데, 운이 나쁘면 버블과 같아요

동작 순서① 피벗 하나 고름 ② 분할: 피벗보다 작은 값은 왼쪽, 큰 값은 오른쪽 ③ 왼쪽·오른쪽 조각에 같은 방법을 반복(조각이 한 칸이면 끝)

퀵 정렬은 기준값 피벗을 하나 골라, 피벗보다 작은 상품은 왼쪽, 큰 상품은 오른쪽으로 나눠요. 그리고 양쪽을 또 같은 방식으로 정렬해요. 피벗이 가운데쯤 값이면 병합처럼 반씩 갈라져서 O(n log n)이에요. 실무에서는 보통 가장 빨라서 이름이 퀵이에요.

문제는 피벗을 잘못 고른 경우예요. 이미 정렬된 [1, 2, 3, 4, 5]에서 맨 앞 1을 피벗으로 잡으면, 1보다 작은 게 하나도 없어요. 왼쪽은 텅 비고 오른쪽에 4개가 몰려요. 다음 피벗 2도 마찬가지예요. 그럼 매번 딱 하나씩만 줄어들어요. 비교는 4 + 3 + 2 + 1번, 버블 정렬의 계단과 똑같은 n(n−1)/2예요. 그래서 최악 O(n²)이에요.

D027 1번이 바로 이 지점을 물었어요. “평균과 최악이 모두 O(n²)”인 걸 찾으라고 했죠. 퀵은 최악은 O(n²)가 맞지만 평균은 O(n log n)이라 ‘모두’에서 빠져요. 퀵의 최악 O(n²)만 떠오르면 낚이는 문제예요. 퀵은 ‘평균은 쪼개는 쪽, 최악은 느린 쪽’에 한 발씩 걸쳐 있다고 기억하세요.

힙병은 철벽, 퀵은 운빨 — 힙·병합은 언제나 n log n. 퀵은 평균 n log n이지만 피벗 운이 나쁘면 n².

→ 이 장면의 결과물: 정렬 여섯 개의 평균·최악이 왜 그런지 다 나왔어요. 남은 건 문제 문장에서 무엇을 보고 고르느냐예요.
