① NS 차트 — 화살표가 없는 순서도

정의: NS 차트(Nassi-Shneiderman Chart, 나씨-슈나이더만 차트)는 프로그램의 논리를 상자 안에 상자를 넣는 방식으로 그리는 도형식 표현 도구예요. 1972년 나씨와 슈나이더만이 구조적 프로그래밍을 그림으로 옮기려고 만들었어요. 구조적 방법론에서 처리 절차(소단위 명세)를 그림으로 적을 때 쓰는 도구라, D018의 구조적 방법론과 한 묶음으로 기억하면 돼요.

왜 생겼나: 전통적인 순서도(flowchart)는 마름모와 화살표로 흐름을 그려요. 화살표는 어디로든 그을 수 있어서, 순서도로 설계하면 코드에서도 GOTO로 여기저기 뛰는 “스파게티”가 되기 쉬웠어요. 1970년대 구조적 프로그래밍 운동은 “모든 논리는 순차·선택·반복 세 구조만으로 표현할 수 있다”는 주장(구조화 정리)에 기대어 GOTO를 줄이자고 했고, NS 차트는 이 철학을 그림 문법 자체에 박아 넣었어요. 상자는 위에서 아래로만 쌓이고, 바깥 상자를 뚫고 다른 곳으로 점프하는 선을 그릴 방법이 아예 없어요. 화살표를 빼앗긴 순서도라고 생각하면 돼요 — 자유를 뺏었더니 질서가 생긴 셈이죠.

구성: 그리는 상자는 세 가지 구조에 하나씩 대응해요. 순차는 직사각형을 위에서 아래로 쌓은 것이에요. 선택은 상자 윗부분에 조건을 적고 역삼각형 모양으로 “예/아니오” 칸을 나눈 뒤, 그 아래에 각 경우의 상자를 나란히 둬요. 값에 따라 여러 갈래로 나뉘는 다중 선택(CASE)도 같은 방식으로 칸을 여러 개 나눠요. 반복은 왼쪽(또는 위·아래)에 반복 조건을 적은 테두리가 안쪽 상자들을 ㄷ자로 감싸는 모양이에요. 테두리가 위에 있으면 조건을 먼저 보는 while, 아래에 있으면 한 번 실행한 뒤 보는 do-while(repeat-until)이에요.

실제로는 이 세 상자를 서로 끼워 넣어요. 아래는 동네 빵집 앱의 “마감 할인 쿠폰 발급” 로직을 NS 차트로 한 칸씩 쌓아 가는 과정이에요. 각 단계에서 새로 들어간 상자를 표시했어요.

장단점: 조건이 여러 겹 중첩된 부분이 상자의 칸 나눔으로 바로 보여서, 복합 조건의 처리를 시각적으로 식별하기 좋고 구조적이지 않은 흐름이 섞일 틈이 없어요. 대신 논리를 조금만 바꿔도 상자 폭을 다시 나눠 그려야 해서 수정이 번거롭고, 중첩이 깊어지면 칸이 오른쪽으로 계속 좁아져요. 그래서 실무 설계 문서보다는 교육·알고리즘 설명용으로 남아 있어요(독일은 1985년 DIN 66261로 표준화까지 했어요).

② 코드 설계 — 번호도 설계 대상이다

정의: 코드 설계는 데이터를 분류하고 조합하기 쉽게, 사물(상품·회원·지역 등)을 짧은 기호나 숫자로 표현하는 규칙을 정하는 기법이에요. 여기서 “코드”는 프로그램 소스가 아니라 상품 번호·학번·지역 번호 같은 식별 번호 체계예요. 현업 감각으로는 테이블의 업무 키나 카테고리 코드 체계를 정하는 일에 가까워요.

왜 필요한가: 번호를 아무렇게나 붙이면 처음엔 편하지만, 나중에 “서울 지점 상품만”, “유제품만” 같은 조회가 필요할 때 번호만 봐서는 아무것도 알 수 없어요. 반대로 번호에 의미를 너무 많이 넣으면 분류가 바뀔 때 번호 전체를 갈아엎어야 하죠. 그래서 번호 체계를 미리 설계해, 이 번호가 어떤 일을 해 줘야 하는지(기능)를 정하고 그에 맞는 방식(종류)을 고르는 거예요. 번호 하나에 이름표·주소·나이를 다 새기려 하면 번호가 이력서가 돼요.

코드의 기능 8가지: 코드가 해 주는 일을 기능이라 불러요. 표준화는 종류·모양·크기처럼 제각각인 정보를 정해진 기준에 따라 통일된 형식으로 나타내는 기능이고, 분류는 같은 특성을 가진 것끼리 묶어 나누는 기능이에요. 식별은 다른 것과 구별되게 하는 기능(코드의 가장 기본적인 일), 배열은 번호 순서대로 나열할 수 있게 하는 기능이에요. 간소화는 긴 정보를 짧게 줄여 표현하는 기능, 연상은 코드만 보고 대상이 무엇인지 떠올릴 수 있게 의미를 담는 기능이에요. 암호화는 외부 사람이 코드만 보고 내용을 알지 못하게 감추는 기능이고, 오류 검출은 입력·관리 중 잘못된 값을 찾아내는 기능이에요 — 바코드·카드 번호의 마지막 검사 숫자(체크 디지트)가 대표 예예요.

③ 코드 종류 6가지 — 번호에 무엇을 담느냐

코드 종류는 “번호 안에 어떤 정보를 담느냐”로 갈라요. 하나씩 정의를 보고, 아래 표에서 같은 상품에 각 방식을 적용한 모습을 비교해요.

순차 코드(Sequence Code)는 일정한 기준(등록순·가나다순 등)에 따라 1, 2, 3… 일련번호를 차례로 붙이는 가장 단순한 코드예요. 만들기 쉽고 짧지만 번호에 의미가 없어서 분류는 못 해요. 출석부 번호가 대표예요. 블록 코드(Block Code, 구분 코드)는 공통 성질을 가진 것끼리 번호 구간(블록)을 먼저 나누고, 각 블록 안에서 일련번호를 붙이는 코드예요. 1000번대는 빵, 2000번대는 케이크처럼요. 전화번호의 지역 번호·국번처럼 앞부분이 같은 무리끼리 공통인 구조가 여기에 해당해요.

그룹 분류식 코드(Group Classification Code)는 블록을 한 단계로 끝내지 않고 대분류·중분류·소분류처럼 여러 단계로 나눠 각 자리를 붙이는 코드예요. 블록 코드가 “구간 하나”라면 그룹 분류식은 “구간 안의 구간”이에요. 입학 연도·학과·번호를 이어 붙인 학번이 이런 모양이에요. 십진 코드(Decimal Code)는 대상을 10진수로 0~9까지 10개씩 계속 나눠 가는 코드로, 도서관 십진 분류(000 총류, 500 기술과학…)가 대표예요. 교재는 국가 번호 880으로 시작하는 상품 바코드를 예로 들어요.

표의 숫자 코드(Significant Digit Code)는 길이·넓이·무게·용량 같은 대상의 물리적 수치를 그대로 코드에 넣는 코드예요. “030-020-500”이 가로 30, 세로 20, 500g이라는 뜻이라면 코드만 보고도 크기를 알 수 있어서 직관적이에요. 연상 코드(Mnemonic Code)는 이름의 일부나 약자를 넣어 코드만 보고 대상을 떠올릴 수 있게 만든 코드예요. 국가 코드 KR·US, 공항 코드 ICN이 이런 방식이에요. 표의 숫자 코드는 “수치”, 연상 코드는 “이름·글자”를 담는다고 가르면 헷갈리지 않아요.

④ 코드 오류 — 사람이 숫자를 틀리는 다섯 가지 방식

정의: 코드 오류는 코드를 기록·입력하는 과정에서 원래 코드와 다르게 적힌 경우를, 어떻게 달라졌는지에 따라 나눈 거예요. 코드의 기능 중 “오류 검출”이 잡으려는 대상이 바로 이것들이에요. 원래 코드가 58316일 때 아래처럼 틀릴 수 있어요.

사본 오류(Transcription Error)는 한 자리를 다른 글자로 잘못 적은 경우로, 필사 오류·오자 오류라고도 해요(58316 → 58916). 전위 오류(Transposition Error)는 이웃한 두 글자의 자리가 서로 바뀐 경우예요(58316 → 58136). 키보드를 빨리 칠 때 가장 흔하죠. 이중 전위 오류(Double Transposition Error)는 전위 오류가 두 군데에서 겹쳐 일어난 경우예요(58316 → 85361). 생략 오류(Omission Error)는 한 글자를 빼먹은 경우(58316 → 5816), 첨가 오류(Addition Error)는 한 글자가 더 들어간 경우예요(58316 → 583316). 생략과 첨가는 자릿수가 달라지니 길이만 세어도 바로 걸러져요.

입력값원래와 비교오류
58916자릿수 같음, 셋째 자리 3 → 9사본(필사·오자)

한 자리만 다른 글자. 길이 검사로는 못 잡고 검사 숫자가 있어야 잡혀요.

입력값원래와 비교오류
58916한 자리 다름사본
58136자릿수 같음, 이웃한 3·1이 자리 바꿈전위

글자 종류는 그대로인데 순서만 바뀌었어요. 숫자 합만 보는 검사로는 못 잡아서, 검사 숫자는 자리마다 가중치를 다르게 줘요.

입력값원래와 비교오류
58916한 자리 다름사본
58136이웃 둘이 바뀜전위
85361바뀐 쌍이 두 군데이중 전위

5·8 쌍과 1·6 쌍이 각각 뒤집혔어요. 전위가 겹쳤으니 이중 전위.

입력값원래와 비교오류
58916한 자리 다름사본
58136이웃 둘이 바뀜전위
85361바뀐 쌍 두 군데이중 전위
5816다섯 자리 → 네 자리, 3이 빠짐생략
583316다섯 자리 → 여섯 자리, 3이 하나 더첨가

자릿수가 줄면 생략, 늘면 첨가. 판정 순서는 “길이부터 → 같으면 한 자리인지 자리바꿈인지”예요.

교재에 따라 여기에 임의 오류(Random Error) — 위 오류가 두 가지 이상 섞여 생긴 경우 — 를 더해 여섯 가지로 소개하기도 해요. 반대로 선지에 나오는 “Sequence Error(순차 오류)”는 코드 오류 종류가 아니에요. 순차는 코드 종류 이름이라는 점에서 일부러 섞어 놓은 함정이에요.
시험에는 이렇게 나와요원래 코드와 잘못 적힌 코드를 나란히 주고 오류 이름을 고르게 해요(1회, 영어 선지). 한 자리만 다른 글자면 Transcription, 이웃 두 자리가 맞바뀌었으면 Transposition, 자릿수가 줄면 Omission, 늘면 Addition이에요. 영어 이름까지 짝으로 기억해 두세요.
