1. 이번 주 범위 지도

공식 출제기준에서 지금까지 끝낸 칸이에요. A1 요구사항 확인 · 분석모델 확인은 세세항목 6개를 모두 돌았고, A2는 감성공학 하나만 남았어요(내일 D010).

2. A1 ① 요구사항과 도출 기법

기능 요구사항시스템이 무엇을 하는가 — 장바구니 담기, 주문 조회, 회원 가입
비기능 요구사항시스템이 얼마나 잘 하는가 — 성능(응답 3초), 보안(암호화), 가용성(99.9%), 사용성·유지보수성

요구 개발 단계는 도출 → 분석 → 명세 → 확인(도분명확). 도출 기법은 “어떤 상황이냐”로 고르는 문제가 대부분이에요.

인터뷰소수 핵심 담당자에게 깊이
설문다수에게 같은 질문 빠르게
관찰실제 업무 현장 지켜보기
워크숍이해관계자가 모여 충돌 조율·합의
브레인스토밍비판 없이 아이디어 확산
문서 분석기존 자료·매뉴얼에서 요구 찾기
“응답 3초 이내”처럼 시간·성능 조건이 붙으면 화면 이야기라도 비기능이에요. “~을 조회할 수 있다”처럼 동작을 말하면 기능.

3. A1 ② UML 한 장

구조 다이어그램 (정적)행위 다이어그램 (동적)
클래스 · 객체 · 컴포넌트 · 배치 · 패키지 · 복합 구조유스케이스 · 시퀀스 · 커뮤니케이션 · 상태 · 활동 · 타이밍
“시간 순서 메시지” = 시퀀스, “이벤트에 따른 상태 변화” = 상태, “물리 노드” = 배치, “처리 흐름·스윔레인” = 활동.

클래스 관계는 선(실선/점선) × 끝 모양 두 가지만 보면 6종이 갈려요.

관계선끝 모양한 줄
연관실선없음서로 참조
집합실선빈 마름모 (전체 쪽)부분이 독립적으로 존재
합성실선채운 마름모 (전체 쪽)생명주기 함께
일반화실선빈 삼각형 (부모 쪽)상속 is-a
실체화점선빈 삼각형 (인터페이스 쪽)인터페이스 구현
의존점선열린 화살표잠깐 사용

유스케이스 관계는 필수냐 조건부냐, 그리고 화살표 방향이 정반대라는 점이 핵심이에요.

«include» 포함«extend» 확장
성격반드시 실행조건이 맞을 때만 실행
화살표점선, 기본 → 포함점선, 확장 → 기본
비유공통 함수 호출if 문으로 붙는 부가 기능

4. A1 ③ 애자일 — 스크럼 · XP

스크럼내용
역할 3제품 책임자(PO, 백로그 우선순위) · 스크럼 마스터(촉진·장애물 제거) · 개발자(2020 가이드 이전엔 “개발팀”)
산출물 3제품 백로그 · 스프린트 백로그 · 증분
이벤트 5스프린트(1개월 이하) · 계획(최대 8h) · 일일 스크럼(15분) · 리뷰(최대 4h, 증분 검사) · 회고(최대 3h, 일하는 방식 개선)
3·3·5 역할·산출물·이벤트. 리뷰 = 결과물을 보고, 회고 = 팀이 일한 방식을 돌아봐요.
짝 프로그래밍둘이 한 화면
TDD테스트 먼저
지속적 통합자주 합치고 빌드
리팩토링동작 유지, 구조 개선
작은 릴리스짧은 주기 배포
고객 상시 참여바로 묻고 답함

위 여섯 칸이 XP 실천이에요. XP 핵심 가치는 의단피용존(의사소통·단순성·피드백·용기·존중).

애자일 선언은 좌우를 뒤집은 선지가 단골: 더 중시하는 쪽은 사작고변(개인과 상호작용 · 작동하는 SW · 고객 협력 · 변화 대응). “포괄적 문서”, “계획 따르기”, “단계별 승인 게이트”는 애자일이 덜 중시하는 쪽이에요.

6. A2 ① UI 요구사항 — 표준 · 지침 · 원칙 · 유형

UI 표준전체 시스템 모든 화면에 공통 적용할 규약 — 화면 구성, 화면 간 이동
UI 지침개발 과정에서 지켜야 할 공통 조건·가이드라인

UI 요구사항은 이 둘에 근거해 “이번 시스템 사용자”가 원하는 UI를 정한 것(정황 시나리오 → 요구 요소 → 요구사항).

※ 자료에 따라 “표준 = 강제, 지침 = 권고”로 설명하기도 해요. 시험 선지는 “화면 구성·이동 규약 = 표준” 키워드로 고르면 돼요.

설계 원칙키워드
직관성처음 봐도 쉽게 이해
유효성사용자의 목적을 정확·완전하게 달성
학습성쉽게 배우고 기억
유연성다양한 사용자·조작 포용, 실수 방지
직유학유 = 이해 · 달성 · 배움 · 포용

OUI사물 자체가 입출력 장치(유기적)웨어러블·IoT 표면

8. 이번 주 함정 모음

  • ‘아닌 것·옳지 않은 것’ 부정형 — 선지마다 O/X를 먼저 표시하고 X를 고르기
  • include ↔ extend 방향: include는 기본 → 포함, extend는 확장 → 기본
  • 빈 삼각형: 실선 = 일반화, 점선 = 실체화
  • OMT 짝 뒤섞기: 동적 = 상태 다이어그램, 기능 = DFD
  • 직관성(바로 이해) ↔ 학습성(쉽게 배움)
  • 목업(정적) ↔ 프로토타입(동적), 와이어프레임 ↔ 스토리보드(최종 참고 문서)
  • UI 표준(통일할 규약) ↔ UI 지침(지킬 조건) 정의 바꿔치기

  1. 쇼핑몰 요구사항 중 비기능 요구사항이 아닌 것은?

  3. 클래스 다이어그램에서 실선 + 빈 삼각형으로 표시하는 관계는?
  4. 스크럼에서 개발자가 매일 약 15분 동안 스프린트 목표 진척을 점검하고 다음 24시간 계획을 조정하는 이벤트는?
  5. XP(eXtreme Programming)의 실천 방법이 아닌 것은?
  6. 자료 사전에서 선택(둘 중 하나)을 뜻하는 기호는?
  7. 민원 신청 화면에서 사용자가 신청 목적을 빠뜨림 없이 정확하고 완전하게 끝마칠 수 있도록 하는 데 중점을 둔 UI 설계 원칙은?
  8. 휘어지는 디스플레이로 만든 손목 밴드처럼, 별도의 화면·입력 장치 없이 사물의 표면과 형태 자체가 입출력 장치가 되는 UI 유형은?
  9. 기획 초기에 색·이미지 없이 선과 박스로 화면 영역 구분과 요소 배치만 잡아, 이해관계자와 레이아웃을 먼저 협의할 때 쓰는 UI 설계 도구는?
  10. 출시 전 사용자 5명에게 실제처럼 화면을 눌러 가며 가입 절차를 따라가게 하고 막히는 지점을 찾는 사용성 테스트에 쓰는, 인터랙션이 적용된 동적 모형은?
